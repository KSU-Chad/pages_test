# RAS 212 — Module 8 Lab
## Building the Safety Gate

**Format:** Eight parts. Set up git and make a feature branch, create a Python package, finish a node from a skeleton, run it in the simulation, test it with services and a parameter, start it from a launch file, write a small service client, then merge your work. Most of the node is written for you. You write the pieces marked `TODO`, which are the same code from lecture.

**Lab computers reset on reboot (Deep Freeze).** Anything not pushed to GitHub is gone. Push before you leave, every session.

**Where everything lives (new in this lab: `mentorpi_nodes`):**

```
~/ros2_ws/
└── src/
    └── mentorpi/                  <- your git repo (a folder, not a package)
        ├── mentorpi_description/  <- Hiwonder's robot model (Module 7)
        ├── mentorpi_bringup/      <- launch files, config, xacro wrapper (Module 7)
        └── mentorpi_nodes/        <- NEW: the Python nodes you write
```

**What you're building and why:** a node called `safety_gate` that sits between the keyboard and the robot. The gate’s `/stop` and `/enable_motion` are one-time requests: you ask the node to do something right now, and you want to know it worked. A topic can’t tell you that. When you publish, you never learn whether anyone received it. A service sends back an answer (success and a message), so you can tell “the gate stopped” from “the gate isn’t even running.” For a safety feature, that confirmation matters. Streams of data, like teleop commands, stay on topics, and settings like max_speed stay as parameters.

```
teleop  --->  cmd_vel_raw  --->  [ safety_gate ]  --->  cmd_vel  --->  Gazebo
                                       ^
                          /stop   /enable_motion   max_speed
```

**This lab is for the simulation.** The gate uses `TwistStamped`, which is what our Gazebo bridge carries. The real MentorPi's driver expects a different message type, and we'll deal with that when we get to the hardware.

```python
import rclpy
from rclpy.node import Node
from geometry_msgs.msg import TwistStamped
from std_srvs.srv import Trigger, SetBool


def clamp(value, low, high):
    """Keep value between low and high."""
    # TODO 1: return value, but never below low and never above high.
    # Hint: combine max() and min(), like Monday's lecture.
    return value


class SafetyGate(Node):

    def __init__(self):
        super().__init__('safety_gate')

        # A ROS parameter: the speed limit, with a default value
        self.declare_parameter('max_speed', 0.3)

        # The node's on/off state, stored on self so callbacks can read it
        self.enabled = True

        # Listen for raw commands, and publish the limited ones
        self.sub = self.create_subscription(
            TwistStamped, 'cmd_vel_raw', self.on_cmd_vel_raw, 10)
        self.pub = self.create_publisher(TwistStamped, 'cmd_vel', 10)

        # Offer two services
        self.create_service(Trigger, 'stop', self.on_stop)
        self.create_service(SetBool, 'enable_motion', self.on_enable_motion)

        self.get_logger().info('safety_gate is ready')

    def on_cmd_vel_raw(self, msg):
        # Motion off: send zeros and stop here
        if not self.enabled:
            self.publish_zero()
            return

        # Read the speed limit fresh each time, so 'ros2 param set' works right away
        limit = self.get_parameter('max_speed').value

        out = TwistStamped()
        out.header = msg.header
        out.twist.linear.x = clamp(msg.twist.linear.x, -limit, limit)
        out.twist.linear.y = clamp(msg.twist.linear.y, -limit, limit)
        out.twist.angular.z = msg.twist.angular.z
        self.pub.publish(out)

    def publish_zero(self):
        # A new TwistStamped is all zeros, so publishing one is a stop command
        out = TwistStamped()
        out.header.stamp = self.get_clock().now().to_msg()
        self.pub.publish(out)

    def on_stop(self, request, response):
        # TODO 2: send one zero command, then fill in the response.
        # Hint: self.publish_zero(), response.success (True), response.message (text)
        return response

    def on_enable_motion(self, request, response):
        # TODO 3: store request.data in self.enabled.
        # If motion was just turned OFF, also send one zero command.
        # Then fill in response.success and response.message
        # (for example 'Motion enabled' or 'Motion disabled').
        return response


def main(args=None):
    rclpy.init(args=args)
    node = SafetyGate()
    try:
        rclpy.spin(node)
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()
```

## Troubleshooting Tips

**Git**
- **`git commit` says "Author identity unknown":** run the two `git config --global` commands from Part 0
- **`git push` asks for a username and password:** you aren't logged in this session. Run `gh auth login --web` again and choose HTTPS
- **`git push` fails with "Permission denied (publickey)":** your remote is the SSH link. Run `git remote -v`. If it starts with `git@github.com:`, switch it: `git remote set-url origin https://github.com/<your-username>/mentorpi.git`
- **`git push` says "no upstream branch":** use `git push -u origin add-safety-gate` the first time
- **`fatal: not a git repository`:** you're not inside `~/ros2_ws/src/mentorpi`. `cd` there and try again
- **`git switch` refuses because of uncommitted changes:** commit them first (or `git stash`)
- **`git merge` reports a conflict:** stop and ask. Don't guess

**Build and run**
- **`Package 'mentorpi_nodes' not found`:** run `source ~/ros2_ws/install/setup.bash` in that terminal
- **`No executable found`:** the `entry_points` line is missing or has a typo in `setup.py`, or you didn't rebuild after adding it
- **`colcon build` can't find the package:** run it from `~/ros2_ws`, not from `src`
- **A new launch file isn't found:** rebuild. `--symlink-install` only covers files that already existed when you built
- **Your edits to `safety_gate.py` don't show up:** check you built with `--symlink-install`. A new file or a new entry point always needs a rebuild
- **`ModuleNotFoundError: No module named 'mentorpi_nodes'`:** you forgot `source install/setup.bash`, or the package never built

**Python errors (read the last line first)**
- **`IndentationError` or `SyntaxError`:** a line is out of place, or a `:`, `)`, or quote is missing. The line number is in the error
- **`NameError: name 'X' is not defined`:** a typo, a missing `import`, or a missing `self.`
- **`AttributeError: 'SafetyGate' object has no attribute 'enabled'`:** check that `self.enabled = True` is in `__init__`
- **A service call never finishes:** `on_stop` or `on_enable_motion` is missing `return response`

**Gate and simulation**
- **Robot doesn't move through the gate:** work the chain. `ros2 topic echo /cmd_vel_raw`, then `ros2 topic echo /cmd_vel`. Stop where the data stops arriving
- **Robot ignores teleop after `/enable_motion` false:** call it again with `{data: true}`
- **Teleop moves the robot but the gate does nothing:** teleop is still publishing to `/cmd_vel`. Check the `-r cmd_vel:=cmd_vel_raw` remap
- **Teleop and the gate both run but nothing moves:** teleop needs `-p stamped:=true`, and the gate needs `use_sim_time:=true`
- **`ros2 param set` fails:** the parameter is a decimal. Write `1.0`, not `1`
- **`waiting for service to become available...`:** the gate isn't running, it's named differently, or you didn't source in that terminal. Check `ros2 service list -t`
