**What you're building:** an action server called `drive_distance`. It drives the robot a set distance, reports progress, and can be canceled. Its commands go **through your safety gate**.

```
ros2 action send_goal --->  [ drive_distance ] --->  cmd_vel_raw  --->  [ safety_gate ]  --->  cmd_vel  --->  Gazebo
                                    ^                                                                          |
                                    |_______________________________  /odom  _________________________________|
```

**This lab is for the simulation.** Teleop is not used here. The action server takes teleop's place. Drive straight only, because turning and strafing are still rough in the sim.

## Part 2 — Finish the Action Server

**Goal:** a working `drive_distance` action server. Most of it is already written. You write four small pieces, marked `TODO 1` through `TODO 4`.

**Create and open the new file:**

**Paste in this skeleton and save:**

```python
import math
import time

import rclpy
from rclpy.action import ActionServer, CancelResponse, GoalResponse
from rclpy.callback_groups import ReentrantCallbackGroup
from rclpy.executors import MultiThreadedExecutor
from rclpy.node import Node
from geometry_msgs.msg import TwistStamped
from nav_msgs.msg import Odometry
from nav2_msgs.action import DriveOnHeading


class DriveDistance(Node):

    def __init__(self):
        super().__init__('drive_distance')

        # Where the robot is, from /odom. None means "no message yet"
        self.x = None
        self.y = None

        # One group that lets callbacks run at the same time
        group = ReentrantCallbackGroup()

        self.create_subscription(
            Odometry, 'odom', self.on_odom, 10, callback_group=group)

        # We publish to cmd_vel_raw so the safety_gate sees our commands
        self.pub = self.create_publisher(TwistStamped, 'cmd_vel_raw', 10)

        self.action_server = ActionServer(
            self,
            DriveOnHeading,
            'drive_distance',
            execute_callback=self.execute,
            goal_callback=self.on_goal,
            cancel_callback=self.on_cancel,
            callback_group=group)

        self.get_logger().info('drive_distance action server is ready')

    def on_odom(self, msg):
        self.x = msg.pose.pose.position.x
        self.y = msg.pose.pose.position.y

    def on_goal(self, goal_request):
        # TODO 1: reject the goal if the distance or the speed is not positive.
        # Hint: goal_request.target.x is the distance, goal_request.speed is the speed.
        # Log a warning, then return GoalResponse.REJECT.

        if self.x is None:
            self.get_logger().warn('Rejected: no odometry yet')
            return GoalResponse.REJECT
        return GoalResponse.ACCEPT

    def on_cancel(self, goal_handle):
        self.get_logger().info('Cancel requested')
        return CancelResponse.ACCEPT

    def send_speed(self, speed):
        msg = TwistStamped()
        msg.header.stamp = self.get_clock().now().to_msg()
        msg.header.frame_id = 'base_link'
        msg.twist.linear.x = speed
        self.pub.publish(msg)

    def execute(self, goal_handle):
        goal = goal_handle.request
        target = goal.target.x
        speed = goal.speed

        # time_allowance is a Duration: seconds plus nanoseconds
        allowance = goal.time_allowance.sec + goal.time_allowance.nanosec * 1e-9
        if allowance <= 0.0:
            allowance = 10.0

        start_x = self.x
        start_y = self.y
        start_time = self.get_clock().now()

        feedback = DriveOnHeading.Feedback()
        result = DriveOnHeading.Result()

        self.get_logger().info(f'Driving {target:.2f} m at {speed:.2f} m/s')

        while rclpy.ok():
            elapsed = (self.get_clock().now() - start_time).nanoseconds / 1e9
            traveled = math.hypot(self.x - start_x, self.y - start_y)

            # Worked example: the cancel branch is done for you
            if goal_handle.is_cancel_requested:
                self.send_speed(0.0)
                goal_handle.canceled()
                result.error_code = DriveOnHeading.Result.NONE
                result.error_msg = 'Canceled'
                break

            # TODO 2: out of time.
            # If elapsed is more than allowance: stop the robot, abort the goal,
            # set error_code to DriveOnHeading.Result.TIMEOUT,
            # set error_msg to 'Ran out of time', and break.

            # TODO 3: arrived.
            # If traveled has reached target: stop the robot, succeed the goal,
            # set error_code to DriveOnHeading.Result.NONE,
            # set error_msg to an empty string '', and break.

            # TODO 4: still driving.
            # Send the speed, put traveled in feedback.distance_traveled
            # (as a float), publish the feedback, then sleep 0.1 seconds.

        elapsed = (self.get_clock().now() - start_time).nanoseconds / 1e9
        result.total_elapsed_time.sec = int(elapsed)
        result.total_elapsed_time.nanosec = int((elapsed % 1.0) * 1e9)
        return result


def main(args=None):
    rclpy.init(args=args)
    node = DriveDistance()
    executor = MultiThreadedExecutor()
    executor.add_node(node)
    try:
        executor.spin()
    except KeyboardInterrupt:
        pass
    finally:
        node.destroy_node()
        rclpy.try_shutdown()
```

## Part 6 — Challenge (Optional): A Watchdog for the Gate

**Goal:** make the gate stop the robot by itself when commands stop arriving.

Remember Module 7: if the thing sending commands disappears, the robot keeps going at the last speed. `time_allowance` doesn't help, because it only guards a *job*. A **watchdog** guards against *silence*.

**Try it first, to see the problem.** Start teleop in a terminal, with the gate running:

**Source the install:**

```bash
source ~/ros2_ws/install/setup.bash
```

**Run teleop through the gate:**

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -p stamped:=true -p use_sim_time:=true -r cmd_vel:=cmd_vel_raw
```

Hold a forward key until the robot moves, then press **Ctrl+C** in the teleop terminal. The robot keeps going. That's the problem.

**The plan:** the gate remembers when the last command arrived. A timer checks every 0.1 s. If the gap is more than `timeout` seconds, it sends one zero command.

**You need four things in `safety_gate.py`:**
1. A new parameter called `timeout`, default 0.5
2. A saved timestamp (`self.last_cmd_time`) that `on_cmd_vel_raw` updates every time a message arrives
3. A timer that calls a new method (`check_timeout`) every 0.1 s, using `self.create_timer(...)`
4. A flag so the warning and the stop command are sent **once**, not 10 times a second

Try writing it yourself. Use the time code from `execute` as a model. If you get stuck:

<details markdown="1">
<summary>Solution</summary>

**In `__init__`, after `self.enabled = True`:**

```python
        self.declare_parameter('timeout', 0.5)
        self.last_cmd_time = self.get_clock().now()
        self.timed_out = True
        self.create_timer(0.1, self.check_timeout)
```

**In `on_cmd_vel_raw`, add these as the first two lines:**

```python
        self.last_cmd_time = self.get_clock().now()
        self.timed_out = False
```

**Add this new method above `publish_zero`:**

```python
    def check_timeout(self):
        timeout = self.get_parameter('timeout').value
        age = (self.get_clock().now() - self.last_cmd_time).nanoseconds / 1e9
        if age > timeout and not self.timed_out:
            self.timed_out = True
            self.publish_zero()
            self.get_logger().warn('No command received, stopping')
```

`self.timed_out` starts as `True` so the gate doesn't warn at startup, before any command has ever arrived.

</details>

**Test it.** Restart the gate (Ctrl+C, then relaunch). Drive with teleop, then press **Ctrl+C** in the teleop terminal. The robot should stop within about half a second, and the gate should print `No command received, stopping`.

**Then test it with your action server.** Send a normal goal. It should finish without the watchdog firing, because the server sends a command every 0.1 s.

**Notes:**
- If driving with teleop feels jerky because of the keyboard's key-repeat delay, raise the timeout to 1.0: `ros2 param set /safety_gate timeout 1.0`
- The timer uses simulation time, so it only works while Gazebo is publishing `/clock`
- This is the gate in the simulation. The real MentorPi's driver has no command timeout and uses a different message type, so the gate still isn't hardware-ready

## Troubleshooting Tips

**Git**
- **`git commit` says "Author identity unknown":** run the two `git config --global` commands from Part 0
- **`git push` asks for a username and password:** you aren't logged in this session. Run `gh auth login --web` again and choose HTTPS
- **`git push` fails with "Permission denied (publickey)":** your remote is the SSH link. Run `git remote -v`. If it starts with `git@github.com:`, switch it: `git remote set-url origin https://github.com/<your-username>/mentorpi.git`
- **`git push` says "no upstream branch":** use `git push -u origin add-drive-action` the first time
- **`fatal: not a git repository`:** you're not inside `~/ros2_ws/src/mentorpi`. `cd` there and try again
- **`git switch` refuses because of uncommitted changes:** commit them first (or `git stash`)
- **A merge reports a conflict (and it's not Part 8):** stop and ask. Don't guess. Never commit a file that still has `<<<<<<<` in it
- **`bags/` shows up in `git status`:** the `.gitignore` line is missing or has a typo. If it was already committed, ask for help

**Build and run**
- **`Package 'mentorpi_nodes' not found`:** run `source ~/ros2_ws/install/setup.bash` in that terminal
- **`No executable found`:** the `drive_distance` line is missing or has a typo in `setup.py` (check the commas), or you didn't rebuild after adding it
- **`ModuleNotFoundError: No module named 'nav2_msgs'`:** `sudo apt install ros-jazzy-nav2-msgs`, then rebuild and source
- **`colcon build` can't find the package:** run it from `~/ros2_ws`, not from `src`
- **`ros2 interface show` says the type is unknown:** you didn't source in that terminal, or `nav2_msgs` isn't installed

**Python errors (read the last line first)**
- **`SyntaxError` on an `if` line:** a single `=` where you meant `>=` or `==`, or a missing `:`
- **`IndentationError`:** a line is out of place. The code inside the `while` loop is indented one level deeper than the `while`
- **`NameError: name 'X' is not defined`:** a typo, a missing `import`, or a missing `self.`
- **`TypeError` about `float` when publishing feedback:** wrap the number with `float(...)`
- **`TypeError: unsupported operand` with `None` (on `self.x`):** `/odom` hasn't arrived yet. The goal check should have rejected it; check TODO 1 and the odometry check

**Action problems**
- **`Waiting for an action server to become available...`:** the server isn't running, the name is wrong, or you didn't source in that terminal. Check `ros2 action list`
- **`Goal was rejected.`:** read Terminal 3. Usually a negative distance or speed, or no `/odom` yet. Is the simulation running?
- **The goal times out (error 721) and the robot never moves:** check the gate is running, and that motion is enabled (`{data: true}`). Then check the server publishes to `cmd_vel_raw` and the gate listens to the same name
- **Feedback stays at 0.0 but the robot moves:** `/odom` isn't reaching the server, or the executor is single-threaded. Check `main`
- **The client never gets a result, but the robot stopped:** a branch is missing `goal_handle.succeed()`, `abort()`, or `canceled()`, or the function is missing `return result`
- **The robot keeps driving after the goal ends:** a branch is missing `self.send_speed(0.0)`
- **Elapsed time looks wrong, or the goal times out instantly:** run the server with `-p use_sim_time:=true` and make sure Gazebo is running
- **The robot moves slower than the goal speed:** the gate limits it to `max_speed`. That's the gate working
- **YAML error in `send_goal`:** use `{target: {x: 1.0}, speed: 0.2, time_allowance: {sec: 10}}`, with a space after each colon, in quotes
- **Cancel does nothing:** the goal already finished, or you cancelled a different server. Cancel while feedback is still printing

**rosbag2**
- **`ros2 bag record` refuses to start:** the output folder already exists. Choose a new name or delete the old folder
- **`ros2 bag play` shows nothing in `topic echo`:** you started `echo` in a terminal that wasn't sourced, or the bag finished before you started it. Play it again
- **The bag player and Gazebo fight:** close Gazebo first. Two publishers on `/odom` give a mixed signal

**Watchdog (Part 6)**
- **Warning prints constantly:** `self.timed_out = True` isn't being set, so the check fires every tick
- **Robot stops while you hold a key:** the key-repeat gap is longer than `timeout`. Raise it to 1.0
- **Watchdog never fires:** `/clock` isn't running, or the gate wasn't started with `use_sim_time`
