## Colcon, Workspaces, Packages & Your First Pub/Sub Nodes

**Prerequisites:** Module 3 lecture (version control conceptually, workspace anatomy, package anatomy)

The tutorial pages themselves have the full code — copy it from there, not from here.

## 1. Using Colcon to Build Packages

📖 **[docs.ros.org: Using colcon to build packages](https://docs.ros.org/en/jazzy/Tutorials/Beginner-Client-Libraries/Colcon-Tutorial.html)**

**What you're doing:** confirming `colcon` is installed, understanding what it does, and building an empty/example workspace for the first time.

- Follow the page's instructions to confirm `colcon` and its extensions are installed
- If the tutorial has you clone example packages to build against, do that now — it gives you real packages to practice on before you write your own
- Build with `colcon build`, then source the result

**Checkpoint:** after building, what's the difference between the `build/` and `install/` folders that appeared? *(Refer back to today's lecture if you're unsure.)*

## 2. Creating a Workspace

📖 **[docs.ros.org: Creating a workspace](https://docs.ros.org/en/jazzy/Tutorials/Beginner-Client-Libraries/Creating-A-Workspace/Creating-A-Workspace.html)**

**What you're doing:** setting up the actual workspace you'll use for the rest of this semester's coding work — `~/ros2_ws` (or wherever your course convention points).

- Follow the page exactly for folder structure (`src/` at minimum)
- Pay attention to the `rosdep install` step — this is how ROS 2 pulls in any missing dependencies your packages need, and it'll save you real debugging time later in the semester if you get in the habit now
- Build and source, same as in Tutorial 1

**Checkpoint:** if you ran `rosdep install` and it reported "all dependencies already satisfied," what does that actually tell you about your system?

## 3. Creating Your First ROS 2 Package

📖 **[docs.ros.org: Creating your first ROS 2 package](https://docs.ros.org/en/jazzy/Tutorials/Beginner-Client-Libraries/Creating-Your-First-ROS2-Package.html)**

**What you're doing:** using `ros2 pkg create` for real, inside the workspace you just built — not a throwaway example this time.

- Create **one Python package** and **one C++ package**, following the tutorial's naming and flag conventions (`--build-type ament_python` / `--build-type ament_cmake`)
- Open `package.xml` in each and compare them side by side — same tags, same structure, different build type
- Build both with `colcon build`, then confirm both show up in `ros2 pkg list`

**Checkpoint:** which fields in `package.xml` did the tutorial have you fill in that weren't just left as placeholders? Why do those particular ones matter?

## 4. Writing a Simple C++ Publisher and Subscriber

📖 **[docs.ros.org: Writing a simple C++ publisher and subscriber](https://docs.ros.org/en/jazzy/Tutorials/Beginner-Client-Libraries/Writing-A-Simple-Cpp-Publisher-And-Subscriber.html)**

**What you're doing:** writing your first real ROS 2 nodes — a publisher (`talker`) and a subscriber (`listener`) — inside your C++ package from Tutorial 3.

- Follow the tutorial's code exactly for `talker.cpp` and `listener.cpp` — this is your first time seeing a full node's structure, so typing/copying it carefully matters more than moving fast
- Pay close attention to the `CMakeLists.txt` edits — this is where a lot of first-timers get stuck, since it's easy to forget to add an executable or a dependency
- Build with `colcon build --packages-select <your_package_name>`, then run `talker` and `listener` in two separate terminals

**Checkpoint:** in the `talker.cpp` code, find the line that actually publishes a message. What topic name and message type is it using?

## Troubleshooting Tips

- **`colcon build` can't find your package:** confirm you're running it from the workspace root (`~/ros2_ws`), not from inside `src/` or the package folder itself
- **C++ build fails but Python didn't (or vice versa):** re-check `CMakeLists.txt` (C++) or `setup.py` (Python) against the tutorial — these are the two most common places to miss a step
- **`ros2 run` says "package not found":** did you `source install/setup.bash` in *this* terminal, after the most recent build? Sourcing doesn't persist across terminal windows
- **Publisher runs but subscriber sees nothing:** double-check both nodes are using the exact same topic name — a one-character typo here fails silently, no error message
- **Stuck on any single step for more than ~10 minutes:** flag your instructor rather than guessing further — today's tutorials are meant to be followed closely, not reverse-engineered
